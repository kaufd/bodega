# Официальная классификация вина — дизайн

Дата: 2026-07-11

## Цель

Заменить единое строковое поле «тип» вина (`Entry.type`, значения вроде «Красное,
сухое») на официальную раздельную классификацию по трём независимым измерениям:
**тип**, **цвет**, **сладость**. Значения фиксированы (выбор, не свободный ввод).

## Классификация

| Измерение | Значения |
|-----------|----------|
| **Тип** | Тихое · Игристое · Креплёное |
| **Цвет** | Красное · Белое · Розовое |
| **Сладость** (зависит от типа) | Тихое: Сухое · Полусухое · Полусладкое · Сладкое |
| | Игристое: Brut · Extra Dry · Dry · Полусладкое |
| | Креплёное: Сухое · Полусладкое · Сладкое |

Значения — отображаемые и хранимые строки (как текущий `Suggestions`, не через
`R.string`). Латиница для игристого, русские метки для остального.

## Модель данных

Три новых nullable-поля в `domain/Entry.kt` и `data/EntryEntity.kt`:

- `wineType: String?` — Тихое / Игристое / Креплёное
- `color: String?` — Красное / Белое / Розовое
- `sweetness: String?` — значение из шкалы, зависящей от `wineType`

Существующее `Entry.type` **остаётся** полем, но используется только категорией
SPIRIT; для WINE больше не заполняется. Поле `type` из ветки WINE редактора убирается.

Справочник значений — новый объект (напр. `WineClassification` в `domain`):
```kotlin
object WineClassification {
    val types = listOf("Тихое", "Игристое", "Креплёное")
    val colors = listOf("Красное", "Белое", "Розовое")
    val sweetnessByType = mapOf(
        "Тихое"     to listOf("Сухое", "Полусухое", "Полусладкое", "Сладкое"),
        "Игристое"  to listOf("Brut", "Extra Dry", "Dry", "Полусладкое"),
        "Креплёное" to listOf("Сухое", "Полусладкое", "Сладкое"),
    )
}
```

## UI редактора (EditScreen)

Порядок винных полей (тип первым):

```
1. Тип        [ Тихое | Игристое | Креплёное ]   ← первым
2. Цвет       [ Красное | Белое | Розовое ]
3. Сладость   [ шкала по выбранному типу ]       ← скрыта, пока тип не выбран
4. Сорт       (grapes, как есть)
5. Страна     (как есть)
6. Год        (как есть)
```

- Компонент выбора: группа чипов **single-select** в существующем стиле —
  невыбранные контурные (как чипы-подсказки), выбранный залитый (как `SelectedChip`).
- **Условная сладость:** набор вариантов = `sweetnessByType[wineType]`. Пока тип не
  выбран — блок сладости скрыт. При смене типа, если текущее значение сладости не
  входит в новую шкалу → сброс в null.
- `EditViewModel.onCategoryChange` сбрасывает `wineType`, `color`, `sweetness` вместе
  с остальными категорийными полями вина.

## Отображение (DetailScreen, ListScreen)

- Подзаголовок вина: `Цвет · Сладость · Тип · Сорт · Страна` (пустые опускаются,
  `distinct`).
- Характеристики карточки (WINE): отдельные строки **Тип**, **Цвет**, **Сладость**,
  затем Сорт, Страна, Год — вместо одной строки «Тип».

расширяется; обновить вызовы в `Entry.toEntity()` и тестах.
